# 在 WorkBuddy 运行真实验收

WorkBuddy首轮真实验收摘要见MCP_INTEGRATION.md。以下提示词可用于复验和多轮偏好测试。不要在提示词或公开输出中粘贴Token。

## 准备项目

解压最新 mcd-regret-less-project.zip，在WorkBuddy中打开解压后的mcd-regret-less项目文件夹。按客户端支持的方式导入skills/mcd-regret-less；若未导入，直接让WorkBuddy读取该文件夹中的SKILL.md及引用文件。本提示词明确要求读取项目，因此不依赖自动发现。

## 第一轮：真实点餐比较

```text
请读取当前项目 skills/mcd-regret-less/SKILL.md，按其中流程执行麦麦后悔药的真实验收。麦当劳MCP已连接。

我的需求：单人到店取餐，想吃巨无霸、中薯和可乐，预算30元，巨无霸必须保留。

先确认我所在的位置、要使用的门店和具体饮料规格。根据实际工具schema查询该门店菜单、相关套餐详情和可用优惠券，围绕我这次请求试算少量具体方案。不要批量枚举或写网络脚本，不下单、不领券、不兑换积分。

用实际结果构建符合 references/data-contract.md 的live输入，完整数据仅保存到项目 private/。用 scripts/planner.py compare 运行离线比较。展示按你的心意、小改一下、预算优先；无可用方案说明原因，预算不够说明差额，缺少原单报价不报节省金额。餐品缺货或30元不够也算有效验收，不用虚构价格或商品凑足三类。

请核对Python结果与实际试算的最终应付价是否一致，并指出遇到的字段映射或运行问题。最后输出脱敏摘要：真实查询日期与时区、实际调用工具名、匿名方案标识、到手餐品及数量、最终应付金额、原单基准（若有）、偏好与比较结果。摘要不要包含Token、地址、账号标识、券码、订单号或支付链接。
```

## 第二轮：保留偏好

在同一对话继续发送：

```text
可乐不要动，预算仍是30元，其他要求保持。请只更新这个偏好，再比较方案。如果需要改商品或当前报价失效，按我的请求重新试算具体方案。不要下单。

请核对所有展示的可选方案都有原要求的可乐和巨无霸，不满足的候选排除。给出脱敏结果摘要。
```

## 第三轮：预算不足

```text
预算改为20元，巨无霸和可乐仍必须保留，其他要求不变。请重新比较；如果没有满足预算的已核验方案，明确说明最低候选与预算的差额。不要替我解除硬偏好，不下单，不凭空声称全菜单最低价。
```

真实门店可能存在20元内方案，不能预设预算一定不足；验收标准是输出忠于真实金额与约束。

## 保存与反馈

保留WorkBuddy实际对话上下文。使用客户端提供的导出/复制能力，保留用户请求、实际工具使用、实现调试与结果，脱敏后再提交到仓库根目录workbuddy.md。不用本提示词或人工编写的成功摘要替代真实对话；是否满足专项奖励仍以官方审核为准。

将真实脱敏摘要用于更新MCP_INTEGRATION.md，核对字段映射、比较金额和偏好保护。WorkBuddy原始对话上下文经脱敏后另存为workbuddy.md；现有验收摘要不替代真实对话。
